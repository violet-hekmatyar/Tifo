# 示例操作：采集 2026-01-01 ~ 2026-10-01 的足球数据

本文件是 `sync_football_data.py` 的一次完整操作示例，采集范围与《football-data.org 数据同步方案 v2+》一致：
原型数据页需要的 8 个热门赛事（英超 / 西甲 / 德甲 / 意甲 / 法甲 / 欧冠 / 世界杯 / 欧洲杯）及其
赛事、赛季、球队、阵容、积分榜、射手榜、球队榜、比赛、重要等级。

- 脚本：`D:\Football-APP\scripts\data-sync\sync_football_data.py`
- 输出：`D:\Football-APP\scripts\sql\seed_football_data_2026.sql`（幂等 SQL，可重复执行）
- 目标库：`south_stand`（MySQL 8.0）
- 只写足球数据域；`sys_user`、`content`、`follow_record` 等用户/内容/互动表完全不在脚本范围内。

---

## 1. 前置准备

1. 在 https://www.football-data.org/client/register 注册免费账号，拿到 token（免费套餐 10 次/分钟）。
2. token 只放在环境变量里，不写进脚本、不提交仓库：

```powershell
$env:FOOTBALL_DATA_API_KEY = "<你的 token>"
```

3. 确认 Python 可用（脚本只用标准库，无需 pip 安装）：

```powershell
py -3 --version
```

---

## 2. 执行采集

在脚本所在目录执行（`--out` 的相对路径以当前目录为基准）：

```powershell
cd D:\Football-APP\scripts\data-sync
py -3 sync_football_data.py --date-from 2026-01-01 --date-to 2026-10-01 `
    --out ..\sql\seed_football_data_2026.sql
```

可选参数：

| 参数 | 说明 |
|---|---|
| `--competitions PL,PD,BL1` | 只处理部分赛事，按需砍请求 |
| `--with-events` | 额外抓取已结束比赛的进球/红黄牌/换人（每场 1 次请求，**本次范围不要开**，见第 8 节） |
| `--events-limit 50` | 配合 `--with-events`，只抓前 50 场 |
| `--refresh` | 忽略缓存 TTL 强制重取 |
| `--api-key <token>` | 不设环境变量时直接传参 |
| `--self-test` | 离线自检，不联网 |

## 3. 本次会抓什么、要多久

| 数据 | 端点 | 次数 |
|---|---|---|
| 赛事信息 | `/competitions/{code}` | 8 |
| 时间段比赛 | `/competitions/{code}/matches?dateFrom=2026-01-01&dateTo=2026-10-01` | 8 |
| 球队 | `/competitions/{code}/teams` | 8 |
| 积分榜 | `/competitions/{code}/standings?season=YYYY` | 14 |
| 射手榜 | `/competitions/{code}/scorers?season=YYYY&limit=100` | 14 |
| 阵容 | `/teams/{id}`（**只补 payload 里没带阵容的球队**，通常 30~40 支） | 约 30~40 |
| **合计** | | **约 75~85 次** |

**阵容不再逐队请求**：`/competitions/{code}/teams` 的响应本身就带每队的完整阵容（实测世界杯 48 队、
欧洲杯 24 队、五大联赛全部都有），脚本直接用这份数据；只有 `CL` 这种 payload 不带阵容的赛事
才回退到 `/teams/{id}`。这同时解决了「国家队阵容 403」——那些队从 payload 里就拿到了。

积分榜/射手榜是 14 次而不是 8 次，因为 **2026-01-01 ~ 2026-10-01 横跨两个赛季**：

| 赛事 | 命中赛季 | 说明 |
|---|---|---|
| 英超/西甲/德甲/意甲/法甲 | 2025/26 + 2026/27 | 上半年赛季收官 + 下半年新赛季开局 |
| 欧冠 | 2025/26 + 2026/27 | 淘汰赛段 + 新联赛阶段 |
| 世界杯 | 2026 | 2026-06 ~ 2026-07 在范围内 |
| 欧洲杯 | 当前赛季（下一届在 2028） | 范围内没有比赛（standings 接口对它返回 404），只有射手榜 |

- 免费套餐 10 次/分钟，脚本强制 **请求间隔 ≥ 6.5 秒**（时间戳记录在 `request_log.json`），
  超过上限会自动等待，不会触发 429。
- **套餐限权（HTTP 403）不再中止整轮**：单个资源受限时跳过并继续，脚本先用 `/competitions/PL`
  探测一次确认 token 有效（探测也 403 才中止并提示是 token 问题）。独立端点 `/teams/{id}` 对
  国家队返回 403，但这些队的阵容已经在 payload 里，所以不影响数据；连续 2 支球队受限后就不再
  请求该赛事其余球队（省请求）。
- 预计耗时 **约 10 分钟**，比赛行数约 1400~1600 场、球员约 4000 人。
- 中断后重跑：已缓存的响应直接复用（赛事/球队 7 天，积分榜/射手榜/比赛 10 分钟），
  并会按 `request_log.json` 补足等待时间，不会重复“打过头”。
- **球队榜、赛季阵容与「重要」等级都由已抓到的数据派生，不产生额外请求。**

## 4. 写入了哪些表

| 表 | 写入方式 | 备注 |
|---|---|---|
| `football_league` | UPSERT | 主键 = 赛事 API ID（2021 / 2014 / 2002 / 2019 / 2015 / 2001 / 2000 / 2018） |
| `football_season` | UPSERT | `season_code` 取赛季起始年（如 `2025`），`season_name` 为 `2025/26` |
| `football_competition_stage` | 先删后插 | 按 `(league_id, season_id)` 范围删 |
| `football_team` | UPSERT | `follower_count` 不触碰 |
| `football_player` | UPSERT | `avatar_url` / `market_value` 等 API 没有的字段不触碰 |
| `team_player` | 先删后插 | 按 `(season, team_id)` 删；阵容按各赛事**当前赛季**写入 |
| `match_info` | UPSERT | 比分、状态、重要等级随时间段复跑自动刷新；不删除旧比赛 |
| `football_standing` | 先删后插 | 只取 `type=TOTAL`（不含主/客场分表） |
| `football_player_competition_stat` | 先删后插 | 射手榜挂在该赛季首个阶段（与 App 默认阶段一致） |
| `football_team_competition_stat` | **UPSERT** | 由积分榜 payload 派生（场次/进球/失球），只更新这三列 |
| `football_team_season_player` | 先删后插 | **App 的球队/球员详情读这张表**；按 `(league, season, team)` 删，转会离队者随刷新消失 |
| `match_event` | 先删后插（按场） | 仅 `--with-events` 时写入 |

其它说明：

- 比赛时间按**北京时间**写入（接口给 UTC，脚本 `+8` 转换），与 `application.yml` 的 `serverTimezone=Asia/Shanghai` 一致。
- **`important_level`（「重要」tab 的开关，后端过滤 `> 0` 并按它倒序）由脚本启发式生成**：
  `3` = 欧冠/世界杯/欧洲杯半决赛及之后，`2` = 这些赛事的其他淘汰赛（附加赛/32 强/16 强/8 强），
  `1` = 联赛积分榜前 6 名之间的对阵，其余 `0`。
  阶段键做了别名归一：接口对同一轮次有多种写法（`LAST_16`→16强、`LAST_32`→32强、`PLAYOFFS`→附加赛、
  `THIRD_PLACE`→三四名决赛），否则这些比赛会被当成普通比赛、不进「重要」tab。
- 球队榜**不用先删后插**：接口只提供场次/进失球，其余列（角球、犯规、评分等）留给人工或后续事件补，
  避免每次同步把它们清零。
- 积分榜/射手榜/球队榜/赛季阵容的 `source` 为 `FOOTBALL_DATA`。
- 一个赛事的多个阶段（欧冠的联赛阶段 / 附加赛 / 16 强 / 8 强 / 4 强 / 决赛）会各自生成一行
  `football_competition_stage`，`stage_name` 已中文。
- 球队信息（国家/主场/建队年/教练）以**字段合并**方式写入：`matches`/`standings` 里的球队对象只有
  5 个字段，不能让它把 `teams`/`scorers` 里的完整信息覆盖成 NULL。
- 一个赛事的多个阶段（欧冠的联赛阶段 / 16 强 / 8 强 / 4 强 / 决赛）会各自生成一行 `football_competition_stage`，
  `stage_name` 已中文（联赛阶段 / 16强 / 8强 / 4强 / 决赛…）。

## 6. 一次性收尾：删除重复名次唯一键 + 退役演示数据

只在**真实数据导入成功之后**执行一次，顺序不能颠倒（先有真实数据，再退役演示数据，App 才不会空窗）。

```powershell
# 6.1 删除 football_standing 上的 uk_standing_scope_rank（V020，幂等）
mysql --default-character-set=utf8mb4 -uroot -p south_stand < D:\Football-APP\scripts\sql\migrations\V020__standings_drop_rank_unique.sql

# 6.2 退役 seed-demo.sql 的演示数据（软删，可回滚）
mysql --default-character-set=utf8mb4 -uroot -p south_stand < D:\Football-APP\scripts\sql\retire-demo-data.sql

# 6.3 校验：演示行在 App 可见条件下应为 0，联赛列表应只剩真实赛事
mysql --default-character-set=utf8mb4 -uroot -p south_stand < D:\Football-APP\scripts\sql\validate-retired-demo-data.sql
```

Docker 方式把 `mysql ... < 文件` 换成：

```powershell
docker cp D:\Football-APP\scripts\sql\retire-demo-data.sql apihub-mysql:/tmp/retire.sql
docker exec apihub-mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot --default-character-set=utf8mb4 south_stand < /tmp/retire.sql'
```

- 为什么删唯一键：`uk_standing_scope_rank (league_id, season_id, stage_id, group_code, rank_no)` 要求同一
  scope 内名次唯一，源数据出现一次重复名次就会让整批导入失败——把上游数据质量问题变成本地硬失败。
  后端只按 scope 等值查询并按 `rank_no` 排序，不依赖该键；`uk_standing_scope_team` 保留作幂等锚。
  `schema.sql` 与 `V015` 已同步移除该键，重跑 `init-demo-data.ps1` 不会把它加回来。
- 为什么软删：`follow_record` / `comment` 等引用不悬空，后端查询一律带 `is_deleted = 0`，App 自然隐藏；
  需要时执行 `retire-demo-data-rollback.sql` 整体恢复（演示内容域不在范围内，见脚本头说明）。
- 退役范围是演示数据集的 ID 段（11=账号 / 12=联赛 / 13=球队 / 14=球员阵容 / 15=比赛事件 /
  20=赛季 / 21=阶段 / 22=积分榜 / 23=球员榜 / 24=球队榜），与真实数据的 football-data.org
  全局 ID（量级 1e3~1e7）完全不相交。
- 副作用：演示数据里独有的「中国足球超级联赛 / 国际足球邀请赛」在免费套餐下没有对应真实赛事，
  退役后 App 只剩 8 个真实赛事。
- 副作用：`scripts/windows` 下依赖演示 ID 的冒烟脚本会失去数据（`smoke-demo-data.ps1`、
  `smoke-football-ranks.ps1`、`smoke-recommendation.ps1`、`smoke-backend-v1-final.ps1`、
  `check-demo-encoding.ps1`、`benchmark-backend-api.ps1`）；它们需要时用 `init-demo-data.ps1` 重建，
  或在临时库跑。

## 7. 导入后校验

```sql
USE south_stand;

-- 7.1 赛事与赛季：5 大联赛 + 欧冠应各两个赛季，世界杯一个
SELECT l.id, l.league_name, l.league_name_en, s.season_code, s.season_name, s.current_flag
FROM football_league l LEFT JOIN football_season s ON s.league_id = l.id
WHERE l.id IN (2021,2014,2002,2019,2015,2001,2000,2018)
ORDER BY l.id, s.season_code;

-- 7.2 比赛数量与状态分布（比赛时间范围应为 2026-01-01 ~ 2026-10-01）
SELECT l.league_name, m.season, m.match_status, COUNT(*) AS cnt
FROM match_info m JOIN football_league l ON l.id = m.league_id
WHERE m.status = 'ACTIVE' AND m.is_deleted = 0
GROUP BY l.league_name, m.season, m.match_status ORDER BY l.league_name, m.season;

-- 7.3 积分榜/球队榜与阶段必须对得上（不一致应为 0 行）
SELECT COUNT(*) AS orphan_standing
FROM football_standing s
LEFT JOIN football_competition_stage g ON g.id = s.stage_id AND g.season_id = s.season_id
WHERE g.id IS NULL;

-- 7.4 「重要」tab：应有数据，且等级分层符合启发式
SELECT important_level, COUNT(*) AS cnt FROM match_info
WHERE status = 'ACTIVE' AND is_deleted = 0 AND important_level > 0
GROUP BY important_level ORDER BY important_level DESC;

-- 7.5 抽查：积分榜、射手榜、球队榜（以英超 2026/27 为例）
SELECT rank_no, team_id, played, won, drawn, lost, goals_for, goals_against, points, form_text
FROM football_standing s JOIN football_season se ON se.id = s.season_id
WHERE s.league_id = 2021 AND se.season_code = '2026' ORDER BY rank_no LIMIT 20;

SELECT p.player_name, p.player_name_en, st.goals, st.assists, st.appearances
FROM football_player_competition_stat st JOIN football_player p ON p.id = st.player_id
JOIN football_season se ON se.id = st.season_id
WHERE st.league_id = 2021 AND se.season_code = '2026' ORDER BY st.goals DESC LIMIT 10;

SELECT t.team_name, ts.played, ts.goals_for, ts.goals_against
FROM football_team_competition_stat ts JOIN football_team t ON t.id = ts.team_id
JOIN football_season se ON se.id = ts.season_id
WHERE ts.league_id = 2021 AND se.season_code = '2026' ORDER BY ts.goals_for DESC LIMIT 10;

-- 7.6 抽查：欧冠淘汰赛树需要的数据（16强/8强/4强/决赛阶段是否都有）
SELECT se.season_code, g.stage_type, g.stage_name, g.sort_order
FROM football_competition_stage g JOIN football_season se ON se.id = g.season_id
WHERE g.league_id = 2001 ORDER BY se.season_code, g.sort_order;

-- 7.7 演示数据是否已退役（应只剩真实赛事）
SELECT id, league_name FROM football_league WHERE status = 'ACTIVE' AND is_deleted = 0 ORDER BY sort_order, id;
```

## 8. 已知限制与注意事项

1. **亚洲杯不在免费套餐内**。杯赛 tab 用世界杯/欧洲杯顶替；如需亚洲杯要付费套餐或换数据源。
2. **不要对本次范围开 `--with-events`**：范围内已结束比赛约 1400 场，每场 1 次请求，
   按 6.5 秒间隔需要约 2.5 小时。需要事件时按赛事/短时间段单独跑：

   ```powershell
   py -3 sync_football_data.py --date-from 2026-09-01 --date-to 2026-09-30 --competitions PL `
       --with-events --events-limit 60 --out ..\sql\events_pl_202609.sql
   ```

3. **跨赛季**：同一赛事会产生两个赛季行、两套阶段与榜单，这是预期行为（App 的赛季下拉正好需要）。
4. **射手榜只含接口返回的前 100 名**（`limit=100`），且只有出场/进球/助攻，
   没有黄牌、射正等明细（接口不提供，这些字段保持 0）。
5. **球队榜只有场次/进球/失球**来自积分榜；角球、犯规、牌面、评分需 `--with-events` 或人工补。
   球员在阵容里的出场/进球数也来自射手榜（每赛季前 100 名），所以阵容页里大部分球员显示 0，
   接口不提供全量球员统计。
6. **国家队阵容正常写入**：`/competitions/{code}/teams` 的 payload 自带阵容，不依赖被限权的 `/teams/{id}`。
   独立端点 `/teams/{id}` 对国家队返回 403，脚本按「受限资源」跳过并记录（SQL 头 + 运行日志），
   连续 2 次受限就停止为该赛事其余球队请求；被跳过的球队**不会**进入 `team_player` /
   `football_team_season_player` 的删除范围，库里已有阵容不会被删空。
7. **阵容按各赛事当前赛季写入**（转会窗后重跑即可刷新）；球员表只 upsert，不删除。
8. **重要等级是启发式**：只区分「淘汰赛深浅」和「联赛前 6 对阵」，不反映真实话题热度；
   需要人工置顶时直接改 `match_info.important_level`，但重跑脚本会按启发式重算覆盖。
9. **ID 与 demo 数据无关**：真实赛事 ID 是 football-data.org 的全局 ID（如英超 2021），
   与 `seed-demo.sql` 的 `1200000000000000x` 系列不冲突；演示数据需按第 6 节显式退役。
10. 失败处理：429 自动退避 60 秒重试，连续 3 次失败即中止并保留已获取数据与缓存；
    修正后重跑即可续上。请求记录在 `request_log.json`，缓存（可随时删）在 `cache/`。
    **HTTP 403 分两种**：资源不在套餐内（跳过继续）与 token 无效（中止并提示）——
    脚本用 `PROBE_PATH = /competitions/PL` 探测区分。中止时不会写出 SQL 文件，
    所以导入前请确认文件时间戳属于本次运行。

## 9. 日常增量更新

赛程/比分/榜单要每天刷新时，用“近 2 天 + 未来 7 天”的小范围跑，请求数约 40 次（阵容/球队命中 7 天缓存）：

```powershell
cd D:\Football-APP\scripts\data-sync
py -3 sync_football_data.py --date-from 2026-10-05 --date-to 2026-10-13 `
    --out ..\sql\update_20261005.sql
```

生成的增量 SQL 同样是幂等的 UPSERT，导入方式与第 5 节相同。赛季初阵容大变动时删掉 `cache/` 再跑一次即可。

## 10. 中英对照表维护

`name_map_zh.json` 由脚本自动补全 ID（新 ID 的中文值置空，SQL 先用英文名兜底），人工只补译：

```json
{
  "competitions": { "PL": "英超", "CL": "欧冠" },
  "teams": {},
  "players": {}
}
```

第一次全量跑完后该文件会多出约 150 个球队 ID、数千个球员 ID（值为 `null`），
按 `null` 搜索批量补译即可；补完不用重新抓数据，重跑脚本（命中缓存）就会输出中文名。
仓库里 `name_map_zh.json` 初始只填了 8 个赛事名，球队/球员留空由脚本自动补 ID。
