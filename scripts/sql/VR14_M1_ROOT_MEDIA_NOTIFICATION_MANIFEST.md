# VR14-M1 根页面媒体与通知基线 Manifest

## 范围

- 固定 DEMO 球队：`30001`～`30006`、`13000000000000001`～`13000000000000024`
- 固定 DEMO 联赛图标：`12000000000000001`～`12000000000000008`
- 固定 DEMO 球员：`40001`～`40010`、VR9 关注球员及现有 P1 旗舰球员
- 固定 DEMO 用户头像：VR11 演员及 VR14 首页实际出现的 `11000000000000001`～`11000000000000010`、`15`、`17`、`22`、`29`，另含验收用户 `10002`
- 固定旧内容：`20001`～`20006`；同步维护已有 `content_media` 与 `content_block` 图片字段
- VR11 通知：只读校验 `10002` 的 8 条、5 未读/3 已读，不重写通知和已读状态

## 媒体资产

新增球队 PNG 均为本地原创开发演示资源，路径统一为 `/demo/p1-media/*.png`。固定数据页球队使用独立队徽文件；联赛图标使用同一套已验证 PNG 资源；球员头像、用户头像和内容封面按计划允许复用既有 P1 PNG。

## 执行与回滚

1. 确认后端静态资源已包含新增球队 PNG。
2. 执行 `VR14_M1_ROOT_MEDIA_NOTIFICATION_SEED.sql`。
3. 执行 `VR14_M1_ROOT_MEDIA_NOTIFICATION_VALIDATOR.sql`，所有 `invalid_count` 必须为 `0`。
4. 再次执行 Seed 与 Validator，确认幂等且无重复。
5. 如需回滚，仅执行 `VR14_M1_ROOT_MEDIA_NOTIFICATION_ROLLBACK.sql`；每个字段仅在仍等于 VR14-M1 写入值时恢复。P1 已拥有的 `130...011/012`、`140...061/067`、`110...001-003` 媒体保持不变，不回滚 P1 所有权；不处理通知读状态。

## 运行时门槛

目标 PNG 必须通过 `HTTP 200 + image/png`，并由 Flutter 正常解码。若返回 JSON/HTML，必须修复资源映射，不得把异常响应当作正式降级证据。
