# VR11-M1 通知演示数据 Manifest

## 范围

- 收件人：`10002`（既有 `test_user`）
- 演员：`11000000000000001`、`11000000000000002`、`11000000000000003`
- 目标内容：`16000000000000901`～`16000000000000906`
- 通知 ID：`17100000000000101`～`17100000000000108`
- `dedup_key`：`VR11:M1:001`～`VR11:M1:008`
- 类型：统一为 `CONTENT_LIKED`，每条使用唯一的演员 + 目标内容组合
- 二级目标：全部为 `NULL`，不引用其他内容下的评论
- 目标：均为收件人本人发布且仍为 `PUBLISHED` 的真实内容
- 初始状态：5 条未读、3 条已读；时间固定并按 ID 倒序展示

## 执行顺序

1. `VR11_M1_NOTIFICATION_SEED.sql`
2. `VR11_M1_NOTIFICATION_VALIDATOR.sql`
3. 连续再次执行 Seed，再执行 Validator，确认数量仍为 8
4. 需要恢复基线时执行 `VR11_M1_NOTIFICATION_ROLLBACK.sql`

## 保护条件

- Seed 在写入前校验收件人、演员、目标内容和保留 ID/去重前缀归属。
- Seed 使用 `ON DUPLICATE KEY UPDATE id=id`，不会覆盖已有通知或读状态。
- Rollback 仅允许同时满足“专用 ID 区间 + `VR11:M1:` 前缀 + 收件人 `10002`”的记录；发现任何归属异常即停止。
- 不创建用户、内容、评论、会话或私信数据，不修改其他通知的已读状态。
